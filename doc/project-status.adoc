== Purpose

`capella2sysmlv2` is a standalone Java model-to-model transformation from Capella models to SysML v2 models represented by the SysON metamodel.

The project must:

* run outside the Capella user interface;
* load real Capella semantic models;
* produce SysON SysML v2 models;
* reuse the open-source Arcadia SysML v2 library;
* delegate final textual export to official SysON tooling;
* remain testable at unit, functional, integration, and product levels.

User instructions are maintained in link:../README.adoc[README.adoc].
Build and contribution instructions are maintained in link:developer-guide.adoc[the Developer Guide].

== Implemented Capabilities

=== Command-Line Contract

The standalone application accepts exactly one input archive and one output directory.

The archive extractor:

* requires exactly one `.project` file and one `.capella` file;
* rejects path traversal and symbolic links;
* limits archive entry count and extracted size;
* refuses to overwrite unmanaged internal content;
* prepares an isolated project directory for each execution.

The application uses `OUTPUT_DIRECTORY/.capella2sysmlv2` for secure project extraction, internal working files, and semantic mapping coverage reports.

=== Headless Capella Loading

The application starts as an Equinox `IApplication` without creating an Eclipse workspace or workbench.

The production loader:

* maps the extracted project directory to its `platform:/resource` URI;
* registers the installed Capella EMF packages and resource factory;
* loads the `.capella` resource directly into a `ResourceSet`;
* requires a typed `org.polarsys.capella.core.data.capellamodeller.Project` root;
* creates and disposes a Capella semantic editing domain without opening an `.aird` file or Sirius session;
* closes model resources deterministically.

Production mappings use typed Capella APIs for source identity, names, and relationships rather than reflective business-feature access.

=== Transformation Engine

`MapperRegistry` resolves the first mapper whose typed source class is compatible with the source element, in registration order, and rejects duplicate source classes.
There is no separate dispatcher or deferred reference resolver.

`TransformationEngine` constructs declared prerequisites recursively before their dependents, then maps features after all construction attempts finish. Source identity determines scope and deduplication; independent sources retain encounter order. Successful targets receive feature mappings once in construction-completion order.

`getCreationDependencies(source)` inspects sources without traceability or mutations. Only dependencies within the supplied scope are resolved. Unsupported, excluded, failed, and out-of-scope prerequisites prevent dependent creation with a diagnostic. Cycles report the involved sources and fail their dependent chain; unrelated mappings continue. Discovery or creation exceptions and null targets exclude the source without retries.

Creation services receive mapped source parents where available and determine final containment. Architecture roots reuse the pre-created targets; ports require mapped owners. Cross-reference feature mappings remain outside the construction graph.

`transform(root, rootName)` traverses the root and its descendants. `transformAll(sources, rootName)` accepts a `Collection<? extends EObject>` without modifying it. No containment-depth sorting or relocation phase remains.
The concrete `TransformationContext` owns the model structure, identity-based `Traceability` (including exclusion state), and `DiagnosticsCollector`. The engine accepts a `rootName` string to name the generated model root; there is no transformation options object or deferred reference resolver.

=== Arcadia Library

`CapellaForSysonResourceSet` in the Equinox application bundle loads `arcadia/library/arcadia.json` from the bundled library using Sirius EMF JSON.

The transformation engine locates required definitions such as `Arcadia::Component` directly in the shared `ResourceSet`.
The generated root is attached to that resource set before target creation, so SysON services can discover the Arcadia library through `SysONEContentAdapter`.

Generated models reference the external Arcadia resource and do not redefine the component concept.

=== Intermediate XMI Persistence

The application writes:

[source,text]
----
OUTPUT_DIRECTORY/<CAPELLA_MODEL_NAME>.sysml.xmi
----

The write is performed through a temporary file followed by an atomic replacement when supported by the file system.

After writing, the application reloads the intermediate XMI and compares element counts by metaclass and the number of resolved Arcadia type references with the in-memory model. It then rewrites the external library references to the SysON library URI. Textual SysML export is planned.

=== Product Distribution

Tycho materializes standalone products for:

* Linux GTK x86_64;
* Windows x86_64.

The Windows distribution contains both `capella2sysmlv2.exe` and the console launcher `capella2sysmlv2c.exe`.

A GitHub Actions workflow is defined for pull requests, `main`, manual runs, and release tags to:

* build with Java 21;
* run regular tests;
* materialize Linux and Windows products for both release targets;
* smoke-test the Capella 7.1.0 archives with IFE on Linux and Windows runners;
* verify the transformation summary and generated model content;
* publish all four archives in a GitHub Release only for tags and after successful acceptance tests.

== Current Mapping Coverage

The production registry is defined by `CapellaMapperCatalog.createMappers()`. Its 18 mappers cover the following source types.

[cols="3,1",options="header"]
|===
|Capella source type |SysML v2 usage

|`Entity`, `SystemComponent`, `LogicalComponent`, `PhysicalComponent` |`PartUsage`
|`OperationalActivity`, `SystemFunction`, `LogicalFunction`, `PhysicalFunction` |`ActionUsage`
|`FunctionInputPort`, `FunctionOutputPort`, `ExchangeItem` |`ItemUsage`
|`ComponentPort` |`PortUsage`
|`FunctionalExchange` |`FlowUsage`
|`ComponentExchange` |`InterfaceUsage`
|`OperationalCapability`, `Capability`, `CapabilityRealization` |`OccurrenceUsage`
|`FunctionalChain` |`ActionUsage`
|===

Components and entities use the Arcadia component definition. Functions and operational activities use the Arcadia function definition.

Mapped usages are constructed after their declared prerequisites. Creation services receive mapped source parents where available and own the final containment; no relocation phase follows. Elements without compatible source ancestors use their existing perspective defaults:

[source,text]
----
Operational Analysis / root functions and packages
System Analysis / Structure and Functions
Logical Architecture / Structure and Functions
Physical Architecture / Structure and Functions
----

The target structure also creates the Arcadia perspective packages, root functions, and system parts required by the current model shape.

The catalog also tracks proposed alignments. For example, `Mission` is a candidate for `Arcadia::Mission` and has no registered mapper.

Each successful transformation writes two Markdown reports under `OUTPUT_DIRECTORY/.capella2sysmlv2/`. The instance report gives coverage and diagnostics for the input model. The meta report describes implemented metaclass and feature mappings, candidate alignments, and the assessment of Arcadia library concepts.

== IFE Reference Result

The standalone product test transforms the In-Flight Entertainment System sample and checks for a successful exit and `Errors: 0`. It checks that the CLI coverage summary matches the instance report and that the generated `In-Flight Entertainment System.sysml.xmi` contains model elements and external Arcadia references.

== Qualification Status

The release workflow runs Maven `clean verify` with Java 21 for each release target. Both profiles include the standalone IFE integration test. Separate Linux and Windows jobs extract and run the Capella 7.1.0 archives before a release tag can publish all four archives.

Official textual SysML export and parser and linker validation remain planned.

== Headless Runtime Constraint

The standalone product still contains SWT, JFace, Eclipse UI, and E4 UI bundles because they belong to the transitive dependency closure of Capella semantic bundles.

The current practical headless criteria are:

* no Eclipse workbench is created;
* no Eclipse workspace is created;
* no `.aird` file or Sirius representation session is opened;
* the Capella semantic editing domain is disposed with the loaded resource;
* no `DISPLAY` variable is required on Linux.

These criteria are verified locally by the standalone product acceptance test. Some UI and Sirius bundles remain in the product's transitive dependency closure, but the bridge only uses Sirius cross-reference support and does not call workspace, workbench, representation, or session APIs.

A physically UI-free distribution would require repackaging Capella semantic classes with modified manifests, which would create a larger maintenance and compatibility commitment.

== Known Gaps

=== Official Textual Export

The project must identify and integrate the official SysON 2026.9.6 textual export API behind a small service boundary.

The implementation must not introduce a local serializer or depend on the SysML v2 Reference Implementation.

=== Parser and Linker Validation

After textual export is available, the generated `.sysml` file must be parsed and linked with official SysON services.
Validation must include Arcadia imports and mapped IFE elements.

=== Mapping Coverage

Additional mappings must be prioritized explicitly and implemented incrementally with focused model assertions, traceability checks, diagnostics, and export validation.

== Roadmap

=== 1. Integrate Official SysON Textual Export

Replace the user-facing intermediate XMI with a textual `.sysml` file while preserving atomic output behavior and failure diagnostics.

=== 2. Validate Generated SysML

Parse and link generated text and verify Arcadia imports, component typing, and mapped IFE elements.

=== 3. Extend Mapping Coverage

Add Capella concepts one at a time through the established transformation engine and test strategy.

== Milestone Completion Criteria

The standalone transformation milestone is complete when:

* the complete repository builds reproducibly with Java 21;
* tagged GitHub Releases publish tested Linux and Windows archives;
* both extracted products transform IFE successfully;
* standalone transformation requires no graphical display, Eclipse workspace, or Sirius session;
* the result is exported to `.sysml` through official SysON tooling;
* generated text passes parser and linker validation;
* generated models reference Arcadia concepts instead of redefining them;
* the acceptance scenario remains automated and release-blocking.

== Guardrails

The project must not:

* introduce Capella or Eclipse UI behavior into the transformation flow;
* open a Sirius representation session merely to load semantic data;
* depend on the SysML v2 Reference Implementation;
* implement or maintain a private textual SysML serializer;
* hardcode local absolute paths;
* let mappers load or navigate the Arcadia library directly;
* place transformation semantics in the engine orchestration, loader, or CLI;
* maintain mutable execution state inside mapper instances.
