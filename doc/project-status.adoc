== Purpose

`capella2sysmlv2` is a standalone Java model-to-model transformation from Capella models to SysML v2 models represented by the SysON metamodel.

The project must:

* run outside the Capella user interface;
* load real Capella semantic models;
* produce SysON SysML v2 models;
* reuse the open-source Arcadia SysML v2 library;
* delegate final textual export to official SysON tooling;
* remain testable at unit, functional, integration, and product levels.

User instructions are maintained in link:../README.adoc[README.adoc].
Build and contribution instructions are maintained in link:developer-guide.adoc[the Developer Guide].

== Transformation Pipeline

[source,text]
----
Capella project zip archive
             |
             v
Secure extraction and project discovery
             |
             v
Equinox headless runtime initialization
             |
             v
Direct .capella semantic model loading
             |
             v
MetaclassId-based mapper dispatch
             |
             v
Shared TransformationContext
             |
             v
SysON SysML v2 model using Arcadia concepts
             |
             v
Intermediate XMI persistence and reload validation
             |
             v
Official textual SysML export                 [not implemented]
             |
             v
SysML parser and linker validation             [not implemented]
----

The transformation layer does not initialize Equinox, load Capella projects, or serialize textual SysML.

== Implemented Capabilities

=== Command-Line Contract

The standalone application accepts exactly one input archive and one output directory.

The archive extractor:

* requires exactly one `.project` file and one `.capella` file;
* rejects path traversal and symbolic links;
* limits archive entry count and extracted size;
* refuses to overwrite unmanaged internal content;
* prepares an isolated project directory for each execution.

The application owns an internal workspace under `OUTPUT_DIRECTORY/.capella2sysmlv2/workspace` and locks its instance location.

=== Headless Capella Runtime

The runtime starts as an Equinox `IApplication` without creating an Eclipse workbench.

The production loader:

* imports or reuses the extracted Eclipse project;
* resolves the `.capella` resource through `platform:/resource`;
* creates a Capella `SemanticEditingDomain`;
* loads the semantic model directly;
* does not open an `.aird` file or Sirius session;
* closes model and runtime resources deterministically.

The `SemanticEditingDomain` and cross-reference adapter remain required by Capella derived-reference helpers.

=== Transformation Engine

Mapper identity is based on `MetaclassId(nsURI, className)`, not runtime `EClass` identity or class name alone.

`TransformationContext` owns all mutable execution state:

* source-to-target traceability;
* generated elements;
* deferred reference resolution;
* diagnostics;
* transformation options;
* access to the Arcadia library resolver.

All source elements are transformed in one shared context and deferred references are resolved once.

=== Arcadia Library

The Equinox transformer loads `arcadia/library/arcadia.json` from the official open-source Arcadia library artifact using Sirius EMF JSON.

The current resolver locates the real `Arcadia::Component` definition.
Mappers access it only through `TransformationContext.libraryResolver()`.

Generated models reference the external Arcadia resource and do not redefine the component concept.

=== Intermediate XMI Persistence

The application writes:

[source,text]
----
OUTPUT_DIRECTORY/<CAPELLA_MODEL_NAME>.sysml.xmi
----

The write is performed through a temporary file followed by an atomic replacement when supported by the file system.

After writing, the application reloads the XMI in the Arcadia library resource set and verifies:

* the generated model is not empty;
* all generated `PartUsage` elements are present;
* every generated part typing still resolves into `arcadialibrary:/arcadia.json`.

This is technical persistence of the SysON model, not textual SysML export.

=== Product Distribution

Tycho materializes standalone products for:

* Linux GTK x86_64;
* Windows x86_64.

The Windows distribution contains both `capella2sysmlv2.exe` and the console launcher `capella2sysmlv2c.exe`.

A tag-triggered GitHub Actions workflow is defined to:

* build with Java 21;
* run regular tests;
* materialize both products;
* execute the IFE acceptance scenario on Linux and Windows runners;
* publish both archives in a GitHub Release only after successful acceptance tests.

The release workflow still requires repository package-access secrets and its first successful tagged execution before it can be considered qualified.

== Current Mapping Coverage

The only production semantic mapping is:

[source,text]
----
Capella LogicalComponent
        -> SysML v2 PartUsage
        -> typed by Arcadia::Component
----

Mapped usages are placed under:

[source,text]
----
Logical Architecture / Structure
----

The target structure also creates the Arcadia perspective packages, root functions, and system parts required by the current model shape.

No other Capella metaclass is supported in production yet.
Functional scenario placeholders do not imply implemented coverage.

== IFE Reference Result

The In-Flight Entertainment System is the current product-level reference model.

[source,text]
----
Transformation completed
Source LogicalComponent count: 23
Generated PartUsage count: 23
Errors: 0
XMI model: /path/to/output/In-Flight Entertainment System.sysml.xmi
----

The persisted model contains 27 `PartUsage` elements in total:

* 23 usages mapped from source logical components;
* 4 generated system parts in the default target structure.

All 27 parts retain an external reference to `Arcadia::Component` after XMI reload.

== Headless Runtime Constraint

The standalone product still contains SWT, JFace, Eclipse UI, and E4 UI bundles because they belong to the transitive dependency closure of Capella semantic bundles.

The current practical headless criteria are:

* no Eclipse workbench is created;
* no `.aird` file or Sirius representation session is opened;
* no `DISPLAY` variable is required on Linux;
* UI bundles must remain inactive during transformation.

The first three criteria are verified.
The last criterion still requires automated bundle-state inspection.

A physically UI-free distribution would require repackaging Capella semantic classes with modified manifests, which would create a larger maintenance and compatibility commitment.

== Known Gaps

=== Release Infrastructure Qualification

The repository must configure package credentials and complete a first tagged Java 21 build.
The resulting GitHub Release links must then be checked from the user documentation.

=== Official Textual Export

The project must identify and integrate the official SysON 2026.7.0 textual export API behind a small service boundary.

The implementation must not introduce a local serializer or depend on the SysML v2 Reference Implementation.

=== Parser and Linker Validation

After textual export is available, the generated `.sysml` file must be parsed and linked with official SysON services.
Validation must include Arcadia imports and all 23 mapped IFE usages.

=== Mapping Coverage

Additional mappings must be prioritized explicitly and implemented incrementally with focused model assertions, traceability checks, diagnostics, and export validation.

== Roadmap

=== 1. Qualify the Release Workflow

Configure `MAVEN_GITHUB_USERNAME` and `MAVEN_GITHUB_TOKEN`, create the first semantic-version tag, and resolve any Java 21 or Windows-specific failure.

=== 2. Automate UI Bundle-State Inspection

Record Equinox bundle states during the acceptance scenario and reject active SWT, Eclipse UI, E4 UI, or workbench bundles.

=== 3. Integrate Official SysON Textual Export

Replace the user-facing intermediate XMI with a textual `.sysml` file while preserving atomic output behavior and failure diagnostics.

=== 4. Validate Generated SysML

Parse and link generated text and verify Arcadia imports, component typing, and mapped IFE elements.

=== 5. Extend Mapping Coverage

Add Capella concepts one at a time through the established transformation engine and test strategy.

== Milestone Completion Criteria

The standalone transformation milestone is complete when:

* the complete repository builds reproducibly with Java 21;
* tagged GitHub Releases publish tested Linux and Windows archives;
* both extracted products transform IFE successfully;
* no forbidden UI bundle is active during transformation;
* the result is exported to `.sysml` through official SysON tooling;
* generated text passes parser and linker validation;
* generated models reference Arcadia concepts instead of redefining them;
* the acceptance scenario remains automated and release-blocking.

== Guardrails

The project must not:

* introduce Capella or Eclipse UI behavior into the transformation flow;
* open a Sirius representation session merely to load semantic data;
* depend on the SysML v2 Reference Implementation;
* implement or maintain a private textual SysML serializer;
* hardcode local absolute paths;
* let mappers load or navigate the Arcadia library directly;
* place transformation semantics in the dispatcher, loader, or CLI;
* maintain mutable execution state inside mapper instances.
