== Purpose

`capella2sysmlv2` is a standalone Java model-to-model transformation from Capella models to SysML v2 models represented by the SysON EMF metamodel.

The project is intended to:

* run outside the Capella user interface;
* load real Capella projects and `.capella` semantic models;
* transform a Capella model into a SysON SysML v2 model;
* reuse concepts from the Arcadia SysML v2 library instead of redefining them;
* delegate textual SysML export to official SysON tooling;
* validate generated text with parser and linker services when they are available;
* remain testable without starting Capella for unit-level concerns.

The target runtime is Java 21 with Capella 7.0.1 and SysON 2026.7.0.

== Transformation Pipeline

[source,text]
----
Capella model
              |
              v
Equinox headless runtime initialization
              |
              v
Capella semantic model loading
              |
              v
MetaclassId-based mapper dispatch
              |
              v
Shared TransformationContext
              |
              v
SysON SysML v2 model
              |
              v
Intermediate XMI persistence              [implemented]
              |
              v
Official SysON textual export             [not implemented yet]
              |
              v
SysML v2 parser/linker validation          [not implemented yet]
----

The transformation layer does not initialize Equinox, load Capella projects, locate mappers directly from other mappers, or serialize SysML text itself.

== Repository Structure

The repository contains two related builds:

* regular Maven modules containing runtime-independent APIs and transformation logic;
* a Tycho reactor under `eclipse/` containing the Capella runtime integration and distributable Equinox product.

=== Regular Maven Modules

`arcadia-library`::
Locates and validates Arcadia SysML v2 library checkouts and exposes library files in deterministic order. It does not contain transformation semantics.

`capella-runtime`::
Defines the runtime initialization boundary. `CapellaRuntime` starts one execution runtime and returns an `InitializedCapellaRuntime` whose lifecycle is explicitly closed by its caller.

`capella-loader`::
Defines the model loading API through `CapellaModelLoader`, `ModelLoadRequest`, and `LoadedCapellaModel`. It depends on runtime abstractions and does not initialize Equinox itself.

`capella2sysmlv2-transformer`::
Contains the model-to-model transformation engine, mapper registry, dispatch logic, traceability, deferred reference handling, target structure creation, diagnostics, and handwritten semantic mappings.

`cli`::
Contains the Picocli command model and an injectable `TransformationService` boundary. The CLI remains independent from the concrete Equinox implementation.

`test-support`::
Provides reusable assertions and resource helpers for unit, functional, and golden-file tests.

`integration-tests`::
Contains functional scenarios and integration-test resources, including the In-Flight Entertainment System scenario.

=== Equinox and Tycho Modules

`eclipse/target-platform`::
Defines the Capella 7.0.1, Eclipse, Sirius, and Kitalpha target platform used by Tycho.

`eclipse/plugins/org.eclipse.capella.sysmlv2.bridge.transformer`::
Adapts the regular Maven transformation code to the Equinox runtime and loads the bundled Arcadia library model.

`eclipse/plugins/org.eclipse.capella.sysmlv2.bridge.application`::
Provides the Equinox `IApplication`, the concrete runtime and loader implementations, Picocli wiring, XMI persistence, and end-to-end transformation orchestration.

`eclipse/features/org.eclipse.capella.sysmlv2.bridge.headless.feature`::
Defines the feature used by the standalone product. It includes the bridge application and transformer bundles and relies on p2 dependency resolution for their runtime closure.

`eclipse/features/org.eclipse.capella.sysmlv2.bridge.feature`::
Defines the feature installable into an existing Capella product. This feature is separate from the standalone product feature.

`eclipse/repository/org.eclipse.capella.sysmlv2.bridge.repository`::
Builds the p2 repository containing the bridge features and bundles.

`eclipse/product/org.eclipse.capella.sysmlv2.bridge.product`::
Defines and materializes the standalone Equinox product for Linux and Windows. The Linux executable is named `capella2sysmlv2`; the Windows distribution provides `capella2sysmlv2.exe` and the console launcher `capella2sysmlv2c.exe`.

`eclipse/official-product-it`::
Contains an automated IFE integration scenario against an official Capella distribution. It installs the bridge feature, launches without `DISPLAY`, checks the transformation summary, and checks the generated XMI file.

== Runtime Responsibilities

=== Runtime Initialization

The application derives the Eclipse workspace from the output directory and initializes the Equinox instance location before Eclipse Resources starts. `EquinoxCapellaRuntime` then verifies the initialized workspace. Closing the runtime saves the workspace and is idempotent.

The product explicitly starts the Equinox infrastructure required before the workspace:

* Equinox Simple Configurator;
* Equinox Common;
* Apache Felix SCR for Declarative Services;
* Equinox Registry and Preferences;
* Eclipse Content Type;
* Eclipse Core Runtime;
* Eclipse Resources.

This ordering is required because the Content Type manager is a Declarative Services component used while the Resources workspace starts.

=== Capella Model Loading

The current production loader is `CapellaSessionLoader`. Its name is historical: it no longer opens a Sirius session.

The archive extractor and loader perform the following operations:

. Securely extract the input zip archive into the internal working directory.
. Require exactly one `.project` file and one `.capella` model.
. Import the project description into the Eclipse workspace at its external location.
. Open and refresh the workspace project.
. Resolve the requested `.capella` file relative to that project.
. Register the project root in the EMF `URIConverter` so that `platform:/resource/<project>/` resolves in the minimal product.
. Create a Capella `SemanticEditingDomain`.
. Load the semantic resource directly from its `platform:/resource` URI.
. Enable proxy resolution while the resource is loaded.
. Return the editing domain, resource set, semantic resource, root objects, and diagnostics through `LoadedCapellaModel`.

No `.aird` file, Sirius `Session`, `SessionManager`, or Eclipse workbench is used in the production loading path.

The `SemanticEditingDomain` and its cross-reference adapter remain necessary because Capella helper code uses inverse and derived references, including `EObjectExt.getReferencers(...)`.

=== Transformation Orchestration

`EquinoxTransformationService` controls one complete execution:

. create the output and internal working directories;
. extract the Capella project and discover its semantic model;
. initialize the runtime;
. load the Capella model;
. find all Capella `LogicalComponent` instances;
. load and resolve the Arcadia SysML v2 library;
. invoke `TransformationEngine.transformAll(...)` with one shared context;
. resolve deferred references once;
. write `<CAPELLA_MODEL_NAME>.sysml.xmi` atomically;
. reload the XMI and verify its generated `PartUsage` elements and Arcadia type references;
. report source, target, and diagnostic counts;
. close the loaded model and runtime.

== Transformation Engine

Mapper identity is based on `MetaclassId(nsURI, className)`. It does not rely on runtime `EClass` object identity or on class names alone.

The main engine concepts are:

`ElementMapper`::
Declares one source `MetaclassId` and transforms a source `EObject` with a shared `TransformationContext`.

`MapperRegistry`::
Stores mappers by stable `MetaclassId`.

`TransformationDispatcher`::
Computes the source metaclass identifier, locates its mapper, invokes it, and reports missing mappings. It contains no semantic transformation logic.

`TransformationContext`::
Owns mutable state for one execution: source-to-target traceability, generated elements, deferred references, diagnostics, options, and access to the Arcadia library resolver.

`TransformationEngine.transformAll(...)`::
Transforms multiple source objects into one target model with one context and one deferred-reference resolution phase.

Mappers are stateless and do not instantiate or locate other mappers.

== Arcadia SysML v2 Library

Generated models must reference concepts from the open-source Arcadia SysML v2 library published by the `eclipse-capella/arcadia-sysmlv2-lib` project.

The current Equinox transformer uses the official artifact:

[source,text]
----
org.eclipse.arcadia:arcadia-library:0.0.3
----

It loads the bundled `arcadia/library/arcadia.json` resource with Sirius EMF JSON and resolves the real `Arcadia::Component` element. Mappers access this model only through `TransformationContext.libraryResolver()`.

The production Arcadia library model comes from the bundled official artifact. Users do not need to locate or configure the library.

== Current Mapping Coverage

The only production semantic mapping currently implemented is:

[source,text]
----
Capella LogicalComponent
        -> SysML v2 PartUsage
        -> typed by Arcadia::Component
----

Generated `PartUsage` elements are placed under the default target structure:

[source,text]
----
Logical Architecture / Structure
----

No additional Capella metaclasses should be considered supported yet. The functional scenario directories for other concepts express intended coverage, not completed production mappings.

== Verified IFE Result

The standalone product has been executed against the real In-Flight Entertainment System Capella project with no `DISPLAY` variable.

[source,text]
----
Transformation completed
Source LogicalComponent count: 23
Generated PartUsage count: 23
Errors: 0
XMI model: /path/to/output/In-Flight Entertainment System.sysml.xmi
----

This proves that the minimal product can initialize Equinox Resources, import a project, load a Capella model, evaluate the Capella cross-reference behavior required by the mapping, resolve `Arcadia::Component`, create the target SysON SysML v2 model, and persist and reload it as XMI while retaining Arcadia references.

It does not yet prove textual `.sysml` export, parser/linker validity, Java 21 compatibility, Windows execution, or the absence of activated UI bundles.

== Headless Runtime Constraint

The materialized product still contains SWT, JFace, Eclipse UI, and E4 UI bundles. They are introduced by the transitive dependency closure of Capella semantic bundles. In particular, `org.polarsys.capella.common` declares dependencies on JFace and EMF Edit UI.

Removing only Capella UI features is therefore insufficient to make the installation physically free of UI bundles.

The current practical headless criterion is:

* no workbench is created;
* no `.aird` or Sirius session is opened;
* no `DISPLAY` variable is required;
* UI bundles are installed only as a transitive constraint and must not become active during a transformation.

The last point still requires automated verification. A physically UI-free distribution would require repackaging the necessary Capella semantic classes with cleaned manifests, which is a larger maintenance and compatibility commitment.

== Build and Product

=== Regular Build

The regular modules are built with:

[source,bash]
----
mvn clean verify
----

Unit tests must not require the Capella runtime or external source repositories.

=== Capella Runtime Product

The Equinox bundles, p2 repository, and standalone product are built with:

[source,bash]
----
mvn -Pcapella-runtime -DskipTests package
----

The products are materialized under:

[source,text]
----
eclipse/product/org.eclipse.capella.sysmlv2.bridge.product/
  target/products/org.eclipse.capella.sysmlv2.bridge.product/linux/gtk/x86_64/
  target/products/org.eclipse.capella.sysmlv2.bridge.product/win32/win32/x86_64/
----

Linux `.tar.gz` and Windows `.zip` product archives are generated under the same module's `target/products/` directory.

The Tycho build currently emits `Misconfigured toolchain` messages in the available Java 25 environment but completes successfully. The intended resolution is to configure and qualify a real Java 21 toolchain rather than suppress those messages.

=== CLI Invocation

The application command is:

[source,bash]
----
capella2sysmlv2 INPUT_ZIP OUTPUT_DIRECTORY
----

The application automatically extracts the project and creates its workspace under `OUTPUT_DIRECTORY/.capella2sysmlv2/workspace`. It writes `<CAPELLA_MODEL_NAME>.sysml.xmi` to the output directory and reports the file path, transformation counts, and diagnostics. This XMI is an intermediate persistence format, not textual SysML.

On Windows, use `capella2sysmlv2c.exe` from PowerShell or `cmd.exe` to keep command output attached to the current console.

== Testing Strategy

=== Unit Tests

Unit tests cover runtime and loader contracts, library discovery, transformation dispatch, mapper registration, diagnostics, traceability, deferred references, target structure, and mapper behavior without starting Capella.

=== Functional Tests

Functional scenarios use small resources to describe and validate focused transformation behavior. Scenarios that mention concepts beyond `LogicalComponent` should not be interpreted as completed production support until their mappers and executable assertions exist.

=== Product and Integration Tests

Product-level tests must exercise the same artifact delivered to users, not only bundles installed into a full Capella workbench product.

The next product test should:

. build or consume the materialized standalone product;
. launch it with `DISPLAY` removed;
. use the zipped IFE project and a fresh output directory;
. assert exit code zero;
. assert 23 source `LogicalComponent` instances;
. assert 23 generated `PartUsage` instances;
. assert zero transformation errors;
. assert that the XMI model exists and retains its Arcadia library references;
. inspect Equinox state and logs to reject activated SWT, Eclipse UI, E4 UI, and workbench bundles.

== Next Steps

=== 1. Automate Standalone Headless Qualification

Update the product integration test to launch the standalone `capella2sysmlv2` executable with the zipped IFE project and an output directory. Record or inspect bundle states after transformation and fail when a forbidden UI bundle is active.

This is the immediate priority because it turns the successful manual IFE run into a reproducible acceptance test.

=== 2. Qualify Java 21

Provide a JDK 21 toolchain and execute both:

[source,bash]
----
mvn clean verify
mvn -Pcapella-runtime package
----

Then run the standalone IFE scenario with that same JDK. Resolve the current Tycho toolchain warnings and document the exact supported Java distribution requirements if necessary.

=== 3. Integrate Official SysON Textual Export

Identify the official SysON 2026.7.0 API that exports a SysML v2 model. Isolate it behind a small export service so that transformation code remains independent from serialization details.

The implementation must not:

* introduce a local SysML serializer;
* depend on the SysML v2 Reference Implementation;
* couple mappers to parser or exporter implementations;
* duplicate EMF in the Equinox product.

=== 4. Replace Intermediate XMI with Textual Output

Use the output directory already provided to the application for the final textual model:

[source,bash]
----
capella2sysmlv2 IFE.zip output/
----

The current XMI persistence already writes atomically and validates its output by reloading it. Preserve those properties when introducing official textual export, and define a dedicated non-zero exit code for exporter failures.

=== 5. Validate Generated SysML

After export is available:

* add a minimal golden file;
* parse the generated `.sysml` with the available SysON parser service;
* run linker validation;
* verify the Arcadia import and `Arcadia::Component` references;
* verify all 23 generated IFE `PartUsage` elements;
* keep parser/linker implementations outside mapper code.

=== 6. Extend Mapping Coverage Incrementally

Add each new Capella concept using the existing TDD sequence:

. add or update a minimal source model;
. add focused target model assertions;
. run the failing test;
. implement the smallest mapper change;
. validate traceability and deferred references;
. validate exported text once export support exists.

Potential mappings must be prioritized explicitly. The presence of placeholder functional scenarios does not define their implementation order.

== Definition of Done for the Current Milestone

The current standalone transformation milestone is complete when all of the following are true:

* the complete repository builds reproducibly with Java 21;
* the standalone product archive is produced by Maven/Tycho;
* a fresh extracted product transforms the IFE project without `DISPLAY`;
* the IFE assertions report 23 source components, 23 target usages, and zero errors;
* no SWT, Eclipse UI, E4 UI, or workbench bundle is active during transformation;
* the result is exported to `.sysml` through official SysON tooling;
* the generated file passes parser and linker validation;
* the generated model references Arcadia concepts instead of redefining them;
* the acceptance scenario is automated and runs from the build.

== Non-Goals and Guardrails

The project must not:

* introduce Capella or Eclipse UI behavior into the transformation flow;
* open a Sirius representation session merely to load semantic data;
* depend on the SysML v2 Reference Implementation;
* implement or maintain a private textual SysML serializer;
* hardcode local absolute paths;
* let mappers load or navigate the Arcadia library directly;
* place transformation semantics in the dispatcher, loader, or CLI;
* maintain mutable execution state inside mapper instances.
