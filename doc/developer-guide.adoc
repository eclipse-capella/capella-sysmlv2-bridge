== Scope

This guide describes how to build, test, package, and release `capella2sysmlv2` from source.

For installation and command-line usage, see link:../README.adoc[the user documentation].
For implemented capabilities and planned work, see link:project-status.adoc[Project Status and Roadmap].

== Development Requirements

The development environment requires:

* JDK 21;
* Maven 3.9 or later;
* Git;
* network access to Maven Central, Eclipse p2 repositories, and GitHub Packages;
* Asciidoctor when rendering documentation locally.

Check the active toolchain before building:

[source,bash]
----
java -version
mvn -version
----

Both commands must report the intended JDK 21 installation.

== GitHub Packages

The build consumes artifacts from the SysON, Sirius, Sirius EMF JSON, Arcadia, and Capella for SysON GitHub Packages repositories.
GitHub Packages may require authentication even when the corresponding source repositories are public.

Create a GitHub personal access token (classic) with the `read:packages` permission, and grant its account read access to the Capella for SysON package if required. Then expose its account and token to Maven:

[source,bash]
----
export MAVEN_GITHUB_USERNAME=<github-account>
export MAVEN_GITHUB_TOKEN=<token-with-read-packages>
----

The committed `.github/maven-settings.xml` file maps these environment variables to all required repository identifiers without storing credentials.
Use it with:

[source,bash]
----
mvn --settings .github/maven-settings.xml clean verify
----

If equivalent servers are already configured in `~/.m2/settings.xml`, the explicit `--settings` argument can be omitted.

Never commit a token or a generated settings file containing a token.

To verify package access without reusing the local Maven cache:

[source,bash]
----
TEST_M2=$(mktemp -d)
mvn --settings .github/maven-settings.xml \
  -Dmaven.repo.local="$TEST_M2" \
  org.apache.maven.plugins:maven-dependency-plugin:3.8.1:get \
  -Dartifact=org.eclipse.arcadia:arcadia-library:0.0.3 \
  -DremoteRepositories=github-arcadia::default::https://maven.pkg.github.com/eclipse-capella/arcadia-sysmlv2-lib
----

== Repository Structure

=== Regular Maven Modules

`capella-loader`::
Contains the model loading contracts and secure Capella project archive extraction.

`capella2sysmlv2-transformer`::
Contains mapper dispatch, transformation context, diagnostics, traceability, target structure creation, and semantic mappings.

`cli`::
Contains the Java command-line entry point and the runtime-independent transformation service contract.

`integration-tests`::
Contains functional and integration scenarios.

`test-support`::
Provides reusable test resources and golden-file assertions.

=== Equinox and Tycho Modules

`eclipse/target-platform`::
Defines the Capella 7.0.1 metamodel, EMF, Equinox, and Kitalpha target platform.

`eclipse/plugins/org.eclipse.capella.sysmlv2.bridge.transformer`::
Adapts the regular transformer to Equinox and loads the bundled Arcadia library.

`eclipse/plugins/org.eclipse.capella.sysmlv2.bridge.mappings`::
Contains typed Capella mapper implementations, the curated alignment backlog, and deterministic candidate-source generation.

`eclipse/plugins/org.eclipse.capella.sysmlv2.bridge.application`::
Implements the Equinox application, typed Capella resource loading, transformation orchestration, and intermediate XMI persistence.

`eclipse/tests/org.eclipse.capella.sysmlv2.bridge.mappings.tests`::
Tests typed mappings against small EMF models and materializes mapper candidate sources from the installed Capella metamodel.

`eclipse/features`::
Defines the standalone headless product feature.

`eclipse/product`::
Materializes and archives the Linux and Windows standalone products.

`eclipse/official-product-it`::
Runs the IFE integration scenario against the packaged standalone product.

== Architecture

The production pipeline is:

[source,text]
----
Input zip archive
        |
        v
Secure project extraction
        |
        v
Capella metamodel package registration
        |
        v
Direct .capella semantic model loading
        |
        v
MetaclassId-based mapper dispatch
        |
        v
Shared TransformationContext
        |
        v
SysON SysML v2 model using Arcadia concepts
        |
        v
Intermediate XMI persistence and reload validation
----

The transformation layer does not initialize Equinox, load projects, or serialize textual SysML.
The engine resolves the definitions required by the generated model structure from the shared `ResourceSet`.
It attaches the generated root to that same `ResourceSet` before dispatching mappers, allowing SysON services to discover Arcadia concepts through `SysONEContentAdapter`.

Mapper lookup uses `MetaclassId(nsURI, className)` rather than runtime `EClass` identity or class names alone.
The Equinox application registers the installed Capella packages, maps `platform:/resource` URIs to the extracted project, and loads the `.capella` resource directly into a Capella semantic editing domain with a Sirius cross-reference adapter. It requires a typed Capella `Project` root and does not create an Eclipse workspace, load an `.aird` resource, or open a Sirius session.
Standalone loading removes TED's session-aware `DataNotifier` immediately after editing-domain creation. The notifier is only useful with a Sirius session and otherwise activates the full Sirius bundle during model notifications; the `SiriusCrossReferenceAdapter` remains installed for direct and inverse derived references.

== Build and Test

=== Regular Build

The required repository build is:

[source,bash]
----
mvn clean verify
----

With explicit GitHub Packages settings:

[source,bash]
----
mvn --settings .github/maven-settings.xml clean verify
----

This build runs the regular unit, functional, and integration tests without starting Capella.

=== Standalone Products

Build the Equinox bundles and Linux and Windows products with:

[source,bash]
----
mvn --settings .github/maven-settings.xml \
  -Pcapella-product \
  -DskipTests \
  clean package
----

The materialized products are created under:

[source,text]
----
eclipse/product/org.eclipse.capella.sysmlv2.bridge.product/
  target/products/org.eclipse.capella.sysmlv2.bridge.product/linux/gtk/x86_64/
  target/products/org.eclipse.capella.sysmlv2.bridge.product/win32/win32/x86_64/
----

The distributable archives are:

[source,text]
----
eclipse/product/org.eclipse.capella.sysmlv2.bridge.product/target/products/
  org.eclipse.capella.sysmlv2.bridge.product-linux.gtk.x86_64.tar.gz
  org.eclipse.capella.sysmlv2.bridge.product-win32.win32.x86_64.zip
----

=== Product Integration Test

Run the complete build and standalone IFE product integration test with:

[source,bash]
----
mvn --settings .github/maven-settings.xml \
  -Pcapella-product,capella-product-it \
  clean verify
----

The materialized standalone product is launched without `DISPLAY`. The test gives it an archive containing only `.project` and `.capella` files, then checks the typed Capella source model, transformation summary, generated XMI model, and Arcadia references.

=== Manual Linux Test

After building the product, download the sample:

[source,bash]
----
curl -L \
  "https://www.eclipse.org/downloads/download.php?file=/capella/samples/7.0.1/InFlightEntertainmentSystem.zip&r=1" \
  -o /tmp/InFlightEntertainmentSystem.zip
----

Run the materialized Linux product:

[source,bash]
----
env -u DISPLAY \
  eclipse/product/org.eclipse.capella.sysmlv2.bridge.product/target/products/\
org.eclipse.capella.sysmlv2.bridge.product/linux/gtk/x86_64/capella2sysmlv2 \
  -vm "$JAVA_HOME/bin/java" \
  /tmp/InFlightEntertainmentSystem.zip \
  /tmp/capella2sysmlv2-output
----

The expected transformation result is 23 source `LogicalComponent` elements, 23 mapped `PartUsage` elements, and zero errors.

=== Mapper Candidate Sources

The Tycho mapping test build inventories all Capella semantic packages contributed through `org.eclipse.emf.ecore.generated_package` and writes one typed Java candidate for every non-abstract metaclass without an implemented mapper.
For the Capella 7.0.1 baseline, it records 252 non-abstract metaclasses and generates 251 candidates under:

[source,text]
----
eclipse/tests/org.eclipse.capella.sysmlv2.bridge.mappings.tests/target/
  generated-mapper-sources/
    mapper-skeletons.txt
    org/eclipse/capella/sysmlv2/bridge/mappings/candidates/<package>/*Mapper.java
----

These files are deterministic build artifacts and are neither compiled nor registered as production mappers.
To implement a mapping, move the relevant candidate into the mapping bundle's handwritten source tree, replace the unsupported-operation body, add coverage metadata and focused tests, then register it explicitly in `CapellaMapperCatalog.createMappers()`.
The curated 17-entry WIP-derived backlog and the complete generated candidate inventory serve different purposes: the former records assessed semantic priorities, while the latter guarantees structural coverage of the installed metamodel.

=== Semantic Mapping Coverage Reports

Every successful product transformation writes deterministic reports to:

[source,text]
----
OUTPUT_DIRECTORY/.capella2sysmlv2/mapping-coverage.json
OUTPUT_DIRECTORY/.capella2sysmlv2/mapping-coverage.md
----

Both reports contain these sections:

`Capella Transformation Coverage`::
Inventories semantic Capella packages contributed through `org.eclipse.emf.ecore.generated_package` whose namespace URI starts with `http://www.polarsys.org/capella/core/` or `http://www.polarsys.org/capella/common/`.
The application resolves each URI through `EPackage.Registry.INSTANCE` and inventories every `EClass` and its `EAllStructuralFeatures`.
The current Capella 7.0.1 baseline is 22 packages and 396 EClasses.
Metaclass metrics use concrete metaclasses as their denominator.
The report distinguishes metaclasses with any registered mapper from complete mappers, for which every applicable structural feature is explicitly mapped or ignored.
Mapped-feature coverage counts mapped declarations; addressed-feature coverage counts mapped plus explicitly ignored declarations; both use all applicable structural feature slots on concrete metaclasses as their denominator.

`Arcadia SysML v2 Library Utilization`::
Inventories named reusable elements reachable from the `Arcadia` `LibraryPackage` only through public `OwningMembership` paths.
Definitions are eligible concepts and Features are eligible features, deduplicated by model identity and qualified name.
Arcadia 0.0.3 currently contributes 14 concepts and 28 features.
Utilization counts the eligible elements explicitly declared by implemented mapper metadata.
Standard SysML targets such as `SysML::Element::declaredName` are not Arcadia features.
Every declared Arcadia reference must resolve in the inventory or report generation fails the transformation.

`Arcadia SysML v2 Library Coverage of Capella`::
Uses an alignment catalog independent from the mapper registry.
Entries have `CONFIRMED`, `CANDIDATE`, `SYSML_STANDARD`, `NO_EQUIVALENT`, or `UNASSESSED` status.
The main metric counts only confirmed metaclass alignments over all concrete Capella metaclasses; candidate backlog entries do not count as mappers or confirmed coverage.
Feature alignments and the unassessed metaclass count are reported separately.

Coverage values are observations only. The build defines no threshold or regression gate.
Linux and Windows smoke jobs append the Markdown report to the GitHub step summary and upload both formats as qualification evidence.

== Release Automation

The `.github/workflows/release.yml` workflow qualifies pull requests, pushes to `main`, manual runs, and release tags.
Release tags must follow strict `vMAJOR.MINOR.PATCH` syntax.

=== Repository Secrets

Configure these Actions secrets in the GitHub repository:

`MAVEN_GITHUB_USERNAME`::
The GitHub account that owns the package access token.

`MAVEN_GITHUB_TOKEN`::
A token with `read:packages` access to the required SysON, Sirius, Arcadia, and Capella for SysON packages. GitHub Packages requires a classic personal access token for Maven authentication.

The workflow uses the built-in `GITHUB_TOKEN` with `contents: write` only when publishing the release.

=== Release Sequence

The workflow performs the following operations:

. validates semantic-version tags and their ancestry from `main`;
. executes the complete Maven, Tycho, and standalone product build with Java 21;
. materializes the Linux and Windows products;
. renames the archives to stable public asset names;
. runs the IFE scenario from the Linux archive without `DISPLAY`;
. runs the IFE scenario from the Windows archive on a Windows runner;
. verifies the `23/23/0` summary, Arcadia references, and Java 21 runtime;
. uploads diagnostic logs after failures;
. creates the GitHub Release for tags only and only after every preceding job succeeds.

The complete Java 21 qualification command used by the workflow is:

[source,bash]
----
mvn --settings .github/maven-settings.xml \
  -Pcapella-product,capella-product-it \
  clean verify
----

The standalone acceptance test demonstrates that semantic model loading and transformation use Capella's semantic editing domain and derived references without requiring a display server, Eclipse workspace, `.aird` file, or Sirius session.

Create a release from an up-to-date `main` branch with:

[source,bash]
----
git switch main
git pull --ff-only
git tag -a v0.1.0 -m "Release v0.1.0"
git push origin v0.1.0
----

The release publishes these stable assets:

* `capella2sysmlv2-linux-x86_64.tar.gz`;
* `capella2sysmlv2-windows-x86_64.zip`.

The user documentation links to the corresponding `/releases/latest/download/` URLs.

Do not move or recreate a published release tag.

== Contribution Rules

New functionality follows a test-driven sequence:

. add or update a minimal source model or metamodel;
. add focused assertions;
. execute the failing test;
. implement the smallest correct change;
. verify target structure, traceability, diagnostics, and references;
. run `mvn clean verify`.

Contributions must not:

* introduce Capella UI, Eclipse UI, or Sirius session behavior into the transformation flow;
* depend on the SysML v2 Reference Implementation;
* implement a private textual SysML serializer;
* hardcode local paths;
* let mappers load the Arcadia library directly;
* place transformation semantics in the dispatcher, loader, or CLI;
* keep mutable execution state in mapper instances.

Contributions must:

* follow the coding guidelines available in releng/resources
